問題 1：重複的 logModal HTML 元素（嚴重）

現象：按下按鈕後「沒有任何反應」— Modal 不顯示。

原因：ip_blacklist.php 中存在 兩個 id="logModal" 的 <div>：

位置行號說明
<body> 開頭L17-28第一個 logModal（inline style）
頁面底部L1121-1132第二個 logModal（CSS class）
⚠️ CAUTION
HTML 規範要求 id 必須唯一。存在兩個相同 id 時，document.getElementById('logModal') 只會返回第一個。

第一個 logModal（L18）存在 CSS 衝突：display 被設定了兩次，triggerFazCollection() 修改的是第一個 modal。

解決方案：移除其中一個 logModal（建議保留 L17-28 的版本）。

問題 2：EventSource URL 使用相對路徑（嚴重）

現象：EventSource 連接失敗，Console 可能出現 404 錯誤。

原因：dashboard.js L344：

eventSource = new EventSource(`api_run_analysis.php?days=${days}`);

使用相對路徑，如果 URL rewrite 或目錄結構不同，路徑可能不正確。

對比原始 Python 版本：原始版本前端和 SSE 都在 web/ 子目錄中，相對路徑正確。新版本結構不同。

解決方案：根據實際部署的 URL 結構調整路徑，或使用絕對路徑。

問題 3：SSE 輸出緩衝問題（中等）

現象：Modal 顯示但內容不更新，或直到完成才突然顯示所有內容。

原因：api_run_analysis.php 缺少關鍵的 output buffer 清除操作。

// 缺少以下程式碼：
while (ob_get_level()) ob_end_flush();
ob_implicit_flush(true);

解決方案：在 api_run_analysis.php 添加 ob_end_flush() 和 ob_implicit_flush(true)。

問題 4：Windows 命令執行路徑問題（中等）

現象：faz_analyzer.php 未實際啟動，log 檔始終為空。

原因：api_run_analysis.php L34 的命令可能因路徑含空格而失敗，且 > NUL 2>&1 吞掉錯誤。

解決方案：給 $phpExec 加引號，將 stderr 重定向到 log 檔而不是 NUL。

問題 5：faz_analyzer.php 資料庫連接可能失敗（中等）

現象：Log 只顯示初始化訊息，然後停止。

原因：作為 CLI 腳本由 start /B 啟動時，__DIR__ 的值可能與 Web 環境不同，DB 配置可能失敗。

解決方案：在 CLI 先手動測試 php faz_analyzer.php，將 stderr 輸出到 log 檔。

問題 6：Log 檔案路徑衝突（低）

現象：SSE 讀到空白資料。

原因：api_run_analysis.php 和 faz_analyzer.php 都會清空 log 檔，存在競爭條件。

解決方案：移除 faz_analyzer.php 中的重複 log 清空操作。
